### 1. Interoperability Mission

KAAMSETU connects state skilling missions, vocational training institutes (ITIs), polytechnics, and corporate CSR training academies directly to the blue-collar labor marketplace.

To establish enterprise credibility, institutional credentials must satisfy five strict criteria:
1. **National Qualification Alignment**: Direct mapping to the National Skills Qualification Framework (NSQF Levels 1 through 8).
2. **Cryptographic Provenance**: Every credential is signed by an authorized signatory whose public key fingerprint is registered on-ledger.
3. **Auditable Formal Lifecycles**: Strict state transitions (`issued` $\rightarrow$ `active` $\rightarrow$ `suspended` $\rightarrow$ `revoked` / `expired`).
4. **Environment Isolation**: Absolute wall between sandbox simulation and production ledger data.
5. **Zero-Downtime Key Lifecycle**: Seamless API key rotation with dual-key overlap windows.

### 2. National Skills Qualification Framework (NSQF) Integration

Every credential record in `public.institutional_credentials` enforces NSQF conformance:

| NSQF Level | Vocational Competency Description | Representative Trades on KAAMSETU |
|---|---|---|
| **Level 2** | Basic manual operations, supervised tasks | Helper Mason, General Laborer, Bar Bending Assistant |
| **Level 3** | Semi-skilled operations with limited autonomy | Assistant Electrician, Plumber Helper, Tile Layer |
| **Level 4** | Skilled independent craftsperson | Domestic Wireman, General Carpenter, Solar PV Installer |
| **Level 5** | Advanced technician, quality supervisor | Master Electrician, HVAC Chiller Technician, Welder 6G |
| **Level 6** | Site engineer, technical supervisor | Site Electrical Supervisor, Structural Masonry Foreman |

The schema enforces `CHECK (nsqf_level >= 1 AND nsqf_level <= 8)`.

### 3. Authorized Institutional Signatories (`institution_authorized_signatories`)

Phase 13 establishes the signatory registry to eliminate impersonation and unverified credential issuance:

```sql
CREATE TABLE public.institution_authorized_signatories (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id uuid NOT NULL REFERENCES public.institutions(id) ON DELETE CASCADE,
  signatory_name text NOT NULL,
  signatory_role text NOT NULL,
  public_key_fingerprint text NOT NULL,
  is_active boolean NOT NULL DEFAULT true,
  authorized_trades text[] NOT NULL DEFAULT '{}',
  created_at timestamptz NOT NULL DEFAULT timezone('utc'::text, now())
);
```

#### Issuance Validation Gate:
When an institution attempts to issue or verify a credential via `src/lib/institution/credential-interop-service.ts`:
1. The engine queries `institution_authorized_signatories` for an active record matching `institution_id` and `public_key_fingerprint`.
2. It verifies that the credential trade falls within `authorized_trades`.
3. If no active signatory matches, the issuance request is rejected with `HTTP 403 Forbidden` (`unauthorized_signatory`).

Verified in Phase 13 Test 9.

### 4. Formal Credential Status Lifecycle

Credentials progress through a strict, auditable state machine:

```
[ ISSUED ] ──> [ ACTIVE ] ──> [ SUSPENDED ] ──> [ REVOKED ] (Terminal)
                  │                │
                  └──> [ EXPIRED ] <┘ (Terminal)
```

1. **`issued`**: Generated by the institution, awaiting worker affirmative consent link.
2. **`active`**: Accepted by the worker, fully visible on the public registry and QR card.
3. **`suspended`**: Temporarily frozen pending investigation of exam malpractice or safety complaints.
4. **`revoked`**: Permanently invalidated due to fraud, forgery, or course disqualification. Revocation is terminal: a revoked credential cannot be returned to active status.
5. **`expired`**: Natural end of time-bounded competency certificates (e.g., safety certifications).

Tested and verified in Phase 13 Test 10: credential transitioned `active` $\rightarrow$ `suspended` $\rightarrow$ `revoked` with timestamp and reason logged.

### 5. Sandbox vs. Production Isolation

Institutional partners require safe integration sandboxes to test their Student Information Systems (SIS) without corrupting live worker registries:

```sql
CREATE TABLE public.institutional_partner_api_keys (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id uuid NOT NULL REFERENCES public.institutions(id) ON DELETE CASCADE,
  key_name text NOT NULL,
  key_prefix text NOT NULL,
  api_key_hash text NOT NULL UNIQUE,
  is_sandbox boolean NOT NULL DEFAULT true,
  rate_limit_per_minute integer NOT NULL DEFAULT 60,
  status text NOT NULL DEFAULT 'active',
  expires_at timestamptz NOT NULL DEFAULT now() + INTERVAL '1 year',
  created_at timestamptz NOT NULL DEFAULT timezone('utc'::text, now())
);
```

- **Sandbox API Keys (`is_sandbox = true`)**:
  - Prefixed with `ks_test_`.
  - Scoped strictly to mock cohort and participant data.
  - Hard-blocked from inserting rows into production `worker_profiles` or issuing live QR cards.
- **Production API Keys (`is_sandbox = false`)**:
  - Prefixed with `ks_live_`.
  - Granted access only after formal institutional verification and signed MoU.

Verified in Phase 13 Test 24.

### 6. Dual-Key Zero-Downtime Rotation

To comply with enterprise security audits, institutions must rotate their API keys annually without interrupting automated nightly sync batches:
1. Institution generates new key `V2` via the dashboard.
2. Both `V1` and `V2` are maintained in `active` status simultaneously during a configurable 30-day transition window.
3. Partner updates downstream ERP credentials to `V2`.
4. Partner revokes `V1`, completing rotation with zero API downtime.

Tested and verified in Phase 13 Test 23.
